# 故障排查

先保存当前应用版本、实际权限后端、服务状态和最近事件，再按下表处理。使用公开测试网址，分享前删除 URL 查询参数、设备地址与 token，参见[隐私说明](Privacy.md)。

本页面向 v0.3.4；不要用旧版成功反馈代替当前版本故障复现。“兼容服务（原生 API）”就是
Stellar 原生后端；官方 Shizuku 是另一条授权与服务路径。

## 安装与授权

| 现象 | 可能原因与下一步 |
| --- | --- |
| APK 无法安装 / 签名冲突 | 未签名 APK 不可直接安装；已签名包需满足 Android 版本、包名、版本号和证书要求。先核对来源及指纹，不直接卸载已有数据 |
| 没有可用权限后端 | 管理器应用已安装不等于服务已启动；回管理器确认服务运行，再刷新状态 |
| 授权被拒绝或不再弹窗 | 在所选管理器检查“岛外打开”的授权，再重试该后端；不会用另一后端绕过拒绝 |
| Shizuku 提示 Binder 来源无法唯一确认 | Stellar 原生服务仍可用。先完成当前接管停服，再停止 Stellar，随后使用官方 Shizuku |
| 无法注册 Controller / 缺少 SET_ACTIVITY_WATCHER | ROM 或当前权限身份不允许该接口；记录型号、ROM、管理器版本和错误，不把授权成功视为系统接口可用 |

## 链接与浏览器

| 现象 | 可能原因与下一步 |
| --- | --- |
| 找不到目标浏览器 | 安装或启用声明了通用 HTTP 与 HTTPS 入口的小米浏览器以外的浏览器，点“刷新状态”；受域名、路径或 MIME 限制的入口不符合筛选条件，原目标不可用时必须手动重选 |
| 改了菜单但仍打开旧目标 | 选择只是草稿；点“开启接管”后才更新运行目标 |
| 观察到网址但仍打开小米浏览器 | 观察模式按设计放行；关闭观察模式并再次点“开启接管” |
| data 为空 / action 不是 VIEW / 无可用网址 | 当前入口不满足接管条件。记录入口与事件，换同一系统功能中能提供公开网址的入口复测 |
| 已拦截却没有打开页面 | 检查是否出现 `am start` 失败或超时，手动确认目标浏览器可用。入队后没有自动回退，可先停用以恢复原跳转 |

“已打开”表示启动命令返回成功，不代表网页加载、账号状态或网络请求成功。如果从未出现捕获事件，确认触发入口实际启动的是 `com.android.browser`，并检查是否有另一 Controller 工具覆盖了接管。

## 停止未完成（先检查 1 分钟）

1. 保留状态文本，确认当前会话属于 Shizuku 还是 Stellar；不要切换后端或只划掉页面。
2. 若原管理器仍可用，且旧调用已结束、按钮允许操作，再点“停用并退出服务”。超时只表示未确认；同步 Binder 调用可能仍未结束，此时不能重复清理或重新开启。
3. 若仍未完成，在对应管理器停止其服务；这会影响依赖该管理器的其他应用，请在能接受中断时操作。必要时自行重启设备。
4. 恢复后检查原链接行为，并确认重新打开“岛外打开”仍处于停用状态。

完成标志为 `停止完成 [所装版本]` 与“已确认 UserService Binder 死亡”。v0.3.4 服务代应为
`30005`。仅看到页面关闭、按钮变灰或一个进程消失都不足以证明完整恢复。

有 ADB 时可查询两个服务进程：

```text
adb shell pidof dev.codex.mibrowserredirector:redirector
adb shell pidof dev.codex.mibrowserredirector:redirector_shizuku
```

停止后应均无 PID。不要用 `am monitor` 调查正在运行的接管，它会干扰当前控制器。

## 提交问题

在仓库 Issues 选择相应模板，写清 APK 版本、设备/ROM、管理器与目标浏览器版本、实际入口、复现步骤及期望/实际行为。附最小脱敏状态片段；如未测试某个后端，直接写“未测试”。构建、脚本或架构问题可先读[开发说明](Development.md)。
